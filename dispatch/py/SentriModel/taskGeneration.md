# Task Generation Specification

## Purpose

This document defines how Sentri generates a `taskGeneration.json`.

This document is responsible only for selecting the most appropriate cybersecurity training task.

It does **not** generate the final playable task.

---

# Activation

This document is inactive by default.

Apply this document ONLY when the user explicitly uses the command:

```
generateTask
```

If the command is not present, ignore every instruction in this document and answer normally as Sentri.

---

# Input

The generator receives exactly one completed `user.json`.

The input profile represents the employee's current cybersecurity state.

The generator must analyze this profile and determine the most appropriate next training task.

---

# Responsibilities

Generate the following:

- id
- type
- difficulty
- phishingScore (if applicable)
- targetDepartment
- targetRank
- knowledgeTags
- behaviorTags
- complexity

Do NOT generate:

- email content
- passwords
- attachments
- links
- documents
- scenarios
- clue analysis
- explanations

Those are generated by the corresponding task generators.

---

# Decision Process

When generating a task:

1. Analyze the employee profile.
2. Identify the employee's weakest cybersecurity skills.
3. Identify behavioral weaknesses.
4. Consider previous training performance.
5. Avoid recently repeated topics whenever possible.
6. Select the single most beneficial training objective.
7. Choose exactly one task type.
8. Select an appropriate difficulty.
9. Produce internally consistent values.

---

# Task Types

Allowed values:

- email
- password
- classification

Select exactly one.

---

# Difficulty

Difficulty ranges from **1–5**.

| Value | Meaning |
|-------:|---------|
| 1 | Very Easy |
| 2 | Easy |
| 3 | Medium |
| 4 | Hard |
| 5 | Expert |

Difficulty should reflect the employee's current ability.

---

# Phishing Score

Represents how convincing the generated phishing attempt should be.

Range:

0–1

Higher values indicate more realistic and more difficult phishing attempts.

If the selected task type is not email, use:

```
0
```

---

# Knowledge Tags

Knowledge tags represent the cybersecurity skills the task is intended to train.

Higher values indicate greater emphasis.

Use values from **0–5**.

Only assign high values to skills relevant to the selected task.

Required fields:

```json
{
  "email": 0,
  "senderVerification": 0,
  "urlInspection": 0,
  "attachmentSafety": 0,
  "domainAwareness": 0,
  "spoofing": 0,
  "credentialProtection": 0,
  "mfa": 0,
  "dataHandling": 0,
  "financialVerification": 0,
  "socialEngineering": 0
}
```

---

# Behavior Tags

Behavior tags represent psychological manipulation techniques emphasized during training.

Use values from **0–5**.

Required fields:

```json
{
  "authority": 0,
  "urgency": 0,
  "fear": 0,
  "curiosity": 0,
  "greed": 0,
  "helpfulness": 0,
  "scarcity": 0,
  "trust": 0,
  "familiarity": 0,
  "reciprocity": 0
}
```

---

# Complexity

Represents the overall complexity of the generated task.

Each value ranges from **1–5**.

Required fields:

```json
{
  "technical": 1,
  "social": 1,
  "evidence": 1,
  "timePressure": 1
}
```

Definitions:

- technical — technical sophistication
- social — social engineering sophistication
- evidence — investigation effort required
- timePressure — urgency imposed on the employee

---

# Internal Consistency

Before producing the output, verify:

- difficulty matches the employee profile
- phishingScore matches the selected difficulty
- knowledgeTags support the selected task type
- behaviorTags support the selected task type
- complexity matches the selected difficulty
- all values are internally consistent

---

# Output Rules

When this document is active:

- Output exactly one JSON object.
- Output valid JSON only.
- Do not output Markdown.
- Do not output explanations.
- Do not output comments.
- Do not output additional text.
- Do not invent fields.
- Do not omit required fields.

---

# Final Validation

Before returning the JSON, verify:

1. The output matches the schema exactly.
2. The JSON is syntactically valid.
3. No required fields are missing.
4. No extra fields have been added.
5. Every value is internally consistent.
6. The selected task is appropriate for the supplied `user.json`.

Return only the JSON object.
